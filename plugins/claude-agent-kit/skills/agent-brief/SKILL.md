# Agent brief

If you cannot describe a task on one page, you are not ready to do it. This skill makes sure you and the user agree on the job **before** you spend effort on it.

Always answer in the language the user writes in.

## Step 1 — Read what you already have

Look at the request, the conversation, the Project instructions and any attached files. Fill in everything you can yourself. Do not ask what you can find.

## Step 2 — Ask at most 3 questions

Only about what is genuinely missing and would change the result. Offer choices when possible ("A: one-page summary, B: detailed 5-page report?"). If nothing important is missing, skip to step 3.

## Step 3 — Write the brief

Use exactly this structure, one page maximum:

```
BRIEF — <task name>

Goal:            what this must achieve, in one sentence
For whom:        the reader / user of the result
Sources:         where the information comes from (files, connectors, user)
Good looks like: 2-3 concrete criteria, or a reference example
Format:          file type, length, language, tone
Limits:          what I must NOT do (send, delete, invent figures, ...)
Check:           how the user (or I) will verify the result
Done when:       the exact deliverable to hand over
```

## Step 4 — Get a "go"

Ask: "Is this right? Reply OK or correct any line." Do not start the work before approval. If the user corrects something, update the brief and show only the changed lines.

## Step 5 — Execute and prove

Do the work following the brief. When you hand it over:
- present it as a **draft**,
- state which "Check" items you verified and how,
- list anything you could not verify or had to assume.

## Rules

- Never invent sources or figures. If data is missing, say so in the brief.
- Anything irreversible (sending, publishing, deleting, paying) stays with the user.
- Keep the brief short. Its value is clarity, not length.
